# sebas QA 验收（qa-acceptance）

带范围选择的验收编排：**先问范围，再派 subagent 经既有入口执行，最后按簇汇报**。
不重复造轮子——一切执行走 `invoke testsuite-*` 固化入口与 `tests/acceptance/COVERAGE.md`
账本，本技能只做范围路由、分派与结论汇总。

## 红线（每次执行前自查）

- 绝不触碰操作员真实实例：端口 9797、真实 `~/.sebas`、真实凭据，只读也是越界。
- 自动化测试一律沙箱（套件入口已内置）；`invoke smoke-real` 属 operator 手跑配方，
  **本技能永远不运行它**，最多在汇报里提示 operator 可自行手跑。
- subagent 只读代码与账本、只经既有入口跑测试；不强杀进程，`/tmp/sbtestsuite.*`
  残留按 sebas-testsuite 技能的规矩报告而非强清。
- 如实汇报：套件红了就是红了，带原始输出摘录；「测不了」的面注明 cause，不粉饰。

## 第一步：询问验收范围

用户已在调用参数里给定范围（如「核心五簇」「全量」）→ 直接进第二步。
未给定 → **必须先问再跑**，用结构化选项（单选）：

1. **核心五簇**——会话管理 / models 管理 / agent workbench / 项目管理 / 通道与监督
   （验收旅程 + 账本复核，硬指标 =100%）
2. **非核心能力**——核心五簇之外的全部能力（矩阵可见性核对 + 进程级 e2e 全量）
3. **全量**——核心 + 非核心 + 浏览器级旅程（三套件 + 账本，最慢最全）
4. **快速冒烟**——进程级 e2e 全量 + 账本头部核对（最快的一键结论）

## 第二步：派 subagent 执行

按范围派 1 个 subagent（general-purpose），把下表对应段落整段写进指令，并附
红线（见上）。subagent 汇报必须含：每条命令的退出码与结果摘录、发现的缺口/豁免、
结论行。主 agent 对 subagent 结论负最终责任，汇报给用户前抽查关键证据行。

| 范围 | subagent 执行内容 |
|---|---|
| 核心五簇 | `invoke testsuite-acceptance`（旅程级，慢）；账本复核：`grep -c '^### Requirement:'` 对五簇各 capability 目录重数，与 COVERAGE.md 核心表逐行核对命中证据；结论按簇给出 命中/基数=100% 与证据指针 |
| 非核心能力 | `invoke testsuite-e2e`（进程级全量）；账本非核心行逐行核对「命中证据 / 豁免 cause / 缺口标注」三态齐全；结论列缺口清单与豁免清单 |
| 全量 | 上述两者 + `invoke testsuite-webui`（浏览器级）；结论合并，浏览器面单列 |
| 快速冒烟 | `invoke testsuite-e2e`；COVERAGE.md 头部核心合计行核对（不重数）；一句话结论 |

执行注意（写进 subagent 指令）：长命令设 600000ms 超时；shell 命令加 `rtk` 前缀；
失败先读输出尾部定位，不盲目重跑；套件入口自带沙箱残留兜底清理。

## 第三步：汇报格式

```
## QA 验收结论（范围：X）

- 套件：testsuite-acceptance ✅ 10/10 ｜ testsuite-e2e ✅ 57/57 ｜ …
- 核心五簇：① 会话管理 16/16 ✅（旅程 session_lifecycle_journey、…） ② …
- 非核心：可见性行 N 条（命中 a / 豁免 b / 缺口 c）
- 缺口与豁免：…（无则写「无」）
- 建议：…（可选）
```

核心五簇范围额外给一句总判定：**达标（=100%）/ 不达标（列差哪几条）**。
验收过程发现的新缺陷建议用 `bd create` 立项（经用户确认后）。
