# 状态库故障排查（sebas.db）

面向操作员的 `sebas.db`（状态库）故障排查入口。覆盖两种启动期保护动作的
区别、日志怎么读、以及隔离文件的手工恢复步骤。

## 两种保护动作：损坏 ≠ 结构不兼容

启动同步（`sebas-db/src/schema.rs`）对库文件只有两种处置，严格区分：

| 情形 | 处置 | 数据去向 |
| --- | --- | --- |
| **库打不开**（损坏：文件截断、非 SQLite 内容等） | 拒绝启动，报错含路径；**一个字节都不动**，绝不重置、绝不隔离 | 原文件原样保留，恢复完全靠手工 |
| **能打开但结构无法调和**（类型不符、多余列、整表缺失、`version_format` 缺失或未知） | **重置**：先把旧库文件改名隔离，再按当前 model 重建空 schema | 旧数据**未迁入新库**，只在隔离文件里 |

只有结构不兼容才触发重置；版本**值**（`schema_meta` 的 `version` 键）不同
从不触发任何重置。

## 重置时发生了什么

日志（WARN）形如：

```text
WARN sebas_db::schema: schema 不兼容: 旧库(含 -wal/-shm)已隔离未删除, 按当前 model 重建空 schema; 旧数据未迁入新库, 如需找回请手工打开隔离文件恢复
    path=/home/you/.sebas/sebas.db
    reason=表 projects 有 model 之外的多余列 `stale`
    quarantined=/home/you/.sebas/sebas.db.reset-1769123456, /home/you/.sebas/sebas.db.reset-1769123456-wal, /home/you/.sebas/sebas.db.reset-1769123456-shm
```

- `reason`：触发重置的结构不兼容点（哪张表、哪一列、或缺哪个版本键）。
- `quarantined`：隔离产物路径。命名规则 **`<db路径>.reset-<unix时间戳>`**，
  `-wal` / `-shm` sidecar 随主文件用**同一时间戳**一并改名（例：
  `~/.sebas/sebas.db.reset-1769123456`、`…-1769123456-wal`、
  `…-1769123456-shm`）。同一秒内多次重置会在时间戳后追加进程号/序号保唯一。
- 重要：重建出的新库是**空的**（只有新 schema）。旧数据没有迁入新库——它
  只存在于隔离文件里。隔离文件是重置前的完整 SQLite 库（重置前旧连接已
  关闭提交，最近一次写入对隔离文件可见），可以正常打开。

## 手工恢复步骤

前提：隔离文件只是改名，没有被删除，因此恢复是普通文件操作。

1. **停掉 sebas core**（以及会碰该库的任何进程），避免恢复中途被写。
2. 找到隔离文件：按日志 `quarantined=` 给出的路径；丢了日志就按通配找
   `~/.sebas/sebas.db.reset-*`（时间戳越大越新）。
3. 按需求二选一：
   - **只取部分数据（推荐）**：不动现有库，另开一个只读会话把要的行导出：
     ```bash
     sqlite3 ~/.sebas/sebas.db.reset-1769123456 ".dump projects" > projects.sql
     # 或挂到现有库上挑行抄回
     sqlite3 ~/.sebas/sebas.db ".recover"                # 现有库损坏时对照用
     ```
   - **整库换回**：把现在的（重置后空）库移开，再成套恢复隔离三件
     （主文件 + `-wal` + `-shm` 必须同名成套，不同名成套可省略 sidecar）：
     ```bash
     mv ~/.sebas/sebas.db ~/.sebas/sebas.db.empty-backup
     mv ~/.sebas/sebas.db.reset-1769123456 ~/.sebas/sebas.db
     ```
     注意：换回的是**旧 schema** 的库——重启后若结构仍与当前 model 不兼
     容，会再次触发重置（再隔离一次）。所以整库换回通常只在「回退了二进制
     版本」时才有意义；一般场景用导出的行手工抄回即可。
4. 重启 core，确认 `/health` 与 `/api/summary` 正常。

## 损坏库的手工处理

库打不开（启动报「打开状态库失败，疑似损坏，拒绝启动且不自动删除文件」）
时系统不会替你处置，恢复同样靠手工：用自己的备份换回，或确认不要后**手工
删除/移走**该文件再启动（系统绝不自动删）。隔离文件那套命名只属于结构不
兼容的重置，损坏路径不会产生任何 `.reset-*` 文件。

## 隔离文件会堆积吗

会（开发期可接受，无自动清理）。确认不再需要后可手工删除
`~/.sebas/sebas.db.reset-*`；建议至少留最近一份直到新库跑稳。
