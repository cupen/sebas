# Gateway P0 Implementation Plan — Provider Router（LLM 网关）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> 用户裁定：本计划只描述架构与代码结构，不写完整实现代码。每个 Task 给出文件清单、对外接口签名、关键设计要点、测试用例清单与 commit 信息；实现细节由执行者按设计文档与要点自行编写。

**Goal:** 在 sebas workspace 新增 `gateway` crate：同端口暴露 Anthropic / OpenAI 双协议面，按模型名纯透传路由到上游 provider，P0 交付推理核心 + 鉴权 + 限流/配额 + 用量统计。

**Architecture:** 通用透传引擎 + 特例处理。axum fallback handler 统一接管 `/v1/*` 与显式前缀 `/anthropic/v1/*`、`/openai/v1/*`；协议嗅探（路径表 + `anthropic-version` header）→ 静态 key 鉴权 → 限流/配额 → model 提取（JSON body 缓冲重放）→ 路由表解析（命名空间/精确/glob/默认）→ reqwest 流式透传（SSE 不缓冲）→ usage tee 落 jsonl。

**Tech Stack:** Rust（gateway crate edition **2021**）、axum 0.8、reqwest 0.12（rustls，无压缩）、tokio 1.40、serde/serde_json、toml 0.8、thiserror 1、tracing、chrono、dirs。

**Beads 映射：** Task N ↔ `sebas-lva.N`（N=1..11）。开工 `bd update sebas-lva.N --claim`，收尾 `bd close sebas-lva.N`。

**设计文档：** `docs/superpowers/specs/2026-08-06-gateway-design.md`（端点清单、协议面矩阵、风险分析以它为准，本文不重复）

## Global Constraints

- gateway crate `edition = "2021"`（member crate 惯例）：**禁止 let-chains**（`if let A = b && cond` 是 edition 2024 语法）；`let ... else` 可用。root crate（`src/`）是 edition 2024，不受影响。
- reqwest 0.12 必须 `default-features = false` + `features = ["rustls-tls", "stream"]`；**禁止启用 gzip/brotli/deflate**（字节级透传前提，压缩会让"字节相等"断言失效）。
- 不引入 yaml 解析库、glob 库、限流库：spec 清单用行扫描解析，glob 与令牌桶手写。
- 命名隔离：crate 名 `gateway`（≠ 现有 `router` crate）；配置段 `[gateway]`（≠ `[router]`）；env 覆盖前缀 `SEBAS_GATEWAY_`。
- 上游 api key 只从 env 读（`api_key_env`）；明文 `api_key` 仅供测试/本地，启动时 warn。任何 key（上游/下游）不落日志、不落 usage jsonl（usage record 记 key 的 `name` 字段）。
- 纯透传：上游响应的 status/body（含错误）原样回传；网关自身错误（401/403/404/413/429/502）按协议面输出对应错误格式：
  - Anthropic: `{"type":"error","error":{"type":...,"message":...}}`
  - OpenAI: `{"error":{"message":...,"type":...,"code":null}}`
- 每个 Task 收尾质量门：`cargo fmt --all -- --check` && `cargo clippy --workspace --all-targets -- -D warnings` && `cargo test --workspace`，全绿才 commit。
- commit 遵循 Conventional Commits（`feat(gateway): ...` 中文摘要）；不 push。
- 测试 env 约定：gateway 测试统一用 `SEBAS_GATEWAY_TEST_UPSTREAM_KEY` / `SEBAS_GATEWAY_TEST_UPSTREAM_KEY_OAI`（各测试进程独立，无竞态）。

### Task 3: 协议识别 proto.rs（sebas-lva.2）

**Files:** Modify `gateway/src/proto.rs`（enum 后追加嗅探逻辑）

**Produces:**
- `Target { protocol: Protocol, path: String }`（path = 剥离显式前缀后的 bare `/v1/...`）
- `resolve_target(headers: &HeaderMap, uri_path: &str) -> Option<Target>`（非 `/v1` → None，proxy 映 404）
- `sniff(headers: &HeaderMap, path: &str) -> Protocol`

**要点:**
- 优先级：显式前缀 `/anthropic/`、`/openai/`（剥离后强制协议）> Anthropic 专属路径表（`/v1/messages`）> OpenAI 专属路径表（chat/completions、responses、embeddings、moderations、images、audio、videos、uploads、batches、fine_tuning、assistants、threads、vector_stores、evals、containers、conversations、chatkit、realtime、organization、projects、completions、content_provenance_checks）> `anthropic-version` header > 默认 OpenAi。
- 碰撞路径（`/v1/models`、`/v1/files`、`/v1/skills`）不进任何路径表，由 header 仲裁；OpenAI SDK 无标识 header，只能作默认。
- 路径匹配必须段边界感知：`/v1/messages` 命中 `/v1/messages/x`，不命中 `/v1/messagesXYZ`。

**测试（inline，6-7 例）：** 显式前缀剥离与强制协议／messages 家族无 header 判 Anthropic／OpenAI 专属路径组／碰撞路径 header 仲裁双向／非 /v1 → None／段边界不误判。

**Commit:** `feat(gateway): 协议嗅探（路径表 + anthropic-version header + 显式前缀挂载）`

### Task 4: 路由表 + model 提取 routing.rs（sebas-lva.3 + sebas-lva.5）

**Files:** Create `gateway/src/routing.rs`；Modify `gateway/src/lib.rs`

**Produces:**
- `RouteTable::from_config(&GatewayConfig) -> RouteTable`
- `RouteTable::resolve(&self, model: Option<&str>, proto: Protocol, key: Option<&KeyConfig>) -> Result<RouteDecision, RouteError>`
- `RouteDecision { provider: String, upstream_model: Option<String> }`（model_map 命中为改名后值；无 model 为 None）
- `RouteError::{NoRoute, ProtocolMismatch { provider }, ModelNotAllowed}`（proxy 分别映 502/400/403）
- `glob_match(pattern, s) -> bool`（手写；无 `*` 时精确相等）、`split_namespace(model) -> Option<(&str,&str)>`、`extract_model_from_body(&Bytes) -> Option<String>`、`extract_model_from_path(&str) -> Option<String>`（仅 `/v1/models/{model}` 单层）

**要点:**
- 解析优先级：`provider/model` 命名空间（provider 须存在，否则按普通 model 名继续走）> 精确 > glob（按 routes 配置顺序取首个命中）> key 级默认 > 全局默认。model 为空（GET 类）直接走默认链。
- allow_models 门禁在 resolve 内做：key 有限制且 model 已知时，无 glob 命中 → `ModelNotAllowed`。
- 协议一致性：解析到的 provider.protocol ≠ 请求 proto → `ProtocolMismatch`，不做协议转换。
- glob 手写语义：`*` 匹配任意字符（含空）；首段必须前缀、末段必须后缀（pattern 以 `*` 结尾则豁免）、中段按序子串查找。

**测试（inline，约 12 例）：** glob 各形态（无星精确/前缀/后缀/中段/不匹配/`*` 通配）／命名空间直达／未知命名空间回退／精确优先于 glob／key 默认优先于全局默认／跨协议拒绝／无默认时 NoRoute／allow_models 放行+拒绝／model_map 改名与未命中原样／无 model 走默认且 upstream_model=None／body 提取（正常/缺字段/非 JSON/非字符串）／path 提取（正常/嵌套拒绝/其它路径）。

**Commit:** `feat(gateway): 路由表（命名空间/精确/glob/默认）与 model 提取、model_map 重命名`

### Task 6: 限流与配额 quota.rs（sebas-lva.7）

**Files:** Create `gateway/src/quota.rs`；Modify `gateway/src/{lib,server}.rs`（AppState 加 `quota: Arc<Quota>`）

**Produces:**
- `Quota`（`Mutex<HashMap<String, KeyUsage>>`，map key = 下游 key 字符串）+ `Default`
- `Quota::check(&self, key: &KeyIdentity) -> QuotaVerdict`：日 token 已超 → Deny（retry_after = 到午夜秒数）；RPM 分钟窗口满 → Deny（retry_after = 窗口剩余秒数）；否则 RPM 计数 +1 放行
- `Quota::record_tokens(&self, key: &str, tokens: u64)`（响应结算后由 usage 路径调用）
- `QuotaVerdict::{Allow, Deny { retry_after_secs, reason } }`

**要点:**
- RPM 用分钟固定窗口（Instant）；日配额用 `chrono::Local::now().date_naive()`，跨天自动清零。窗口/日期翻转逻辑集中在 check/record_tokens 内。
- token 是事后记账：本请求消耗在响应结算后补记，下一次 check 才生效（设计文档认可的近似语义）。

**测试（inline，5 例）：** RPM 到限 Deny 且 retry_after∈(0,60]／拨回 window_start 模拟窗口重置放行／record_tokens 到顶后 Deny／拨回 day 模拟跨天重置／无限制 key 永放行。（同模块测试可直接操作内部 map 构造时间态。）

**Commit:** `feat(gateway): per-key RPM 令牌桶与每日 token 配额记账`

### Task 7: 透传引擎 proxy.rs（sebas-lva.4 前半 + sebas-lva.8 前半）

**Files:**
- Create: `gateway/src/proxy.rs`、`gateway/tests/proxy_smoke_test.rs`
- Modify: `gateway/src/{lib,server}.rs`（AppState 加 `table: Arc<RouteTable>`；fallback 换成 `proxy::handle`；删 501 placeholder）

**Produces:**
- `proxy::handle(State<AppState>, Request) -> Response`
- `AppState.table: Arc<RouteTable>`

**要点（行为契约，Task 9 contract tests 逐端点断言）：**
- 请求侧：剥离 `host/connection/content-length/transfer-encoding/authorization/x-api-key/keep-alive/te/trailer/upgrade`；Anthropic 注入 `x-api-key: <上游key>`、OpenAI 注入 `authorization: Bearer <上游key>`；`anthropic-version`/`anthropic-beta` 等业务 header 原样透传；query string 保留。
- body 策略：JSON 的 POST/PUT/PATCH → `to_bytes(body, max_body_bytes)` 缓冲（超限 413）用于 model 提取；其余（GET/DELETE/multipart）流式不缓冲（`Body::wrap_stream(body.into_data_stream())`）。model_map 命中且确有改名时重写缓冲 JSON 的 `model` 字段（解析失败原样转发——rename 不阻断透传）。
- 响应侧：status 原样；剥离 `connection/transfer-encoding/keep-alive/te/trailer/upgrade/content-length`；`content-type: text/event-stream` → `bytes_stream()` 逐 chunk `Body::from_stream` 透传不缓冲（Task 8 在此加 tee）；非 SSE → 缓冲回传。
- 错误映射：非 /v1 路径 404；quota Deny → 429 + `retry-after` header；`ModelNotAllowed` → 403 `permission_error`；`ProtocolMismatch` → 400 `invalid_request_error`；`NoRoute` → 502 `no_route`；上游连接/读取失败 → 502 `upstream_error`。
- 纯函数拆分以便单测：`filtered_request_headers(src, proto, upstream_key)`、`filtered_response_headers(src)`、`rename_model_in_body(body, upstream_model)`。

**测试：**
- inline 单元 4 例：请求剥离+注入 Anthropic key（含下游 key 不泄漏断言）／OpenAI Bearer 注入／响应 hop-by-hop 剥离／rename 改写 JSON 且保留其它字段（非 JSON 原样）。
- `proxy_smoke_test.rs` 2 例：内联 mini 上游（axum 单路由回固定 JSON 并记录 header）验证 JSON POST 端到端透传 + key 注入 + 业务 header 透传；不可达上游（127.0.0.1:1）→ 502 `upstream_error`。

**Commit:** `feat(gateway): 透传引擎（header 改写、model rename、SSE 原始透传、协议面错误映射）`

### Task 8: SSE usage tee + 用量落盘（sebas-lva.4 后半 + sebas-lva.8 后半）

**Files:**
- Create: `gateway/src/sse.rs`、`gateway/src/usage.rs`
- Modify: `gateway/src/{lib,server,proxy}.rs`（AppState 加 `sink: UsageSink`；proxy 的 SSE 分支加 tee、非 SSE 分支解析 usage、统一结算）

**Produces:**
- `sse::UsageInfo { input_tokens, output_tokens, cache_read_tokens, cache_creation_tokens: Option<u64> }`
- `sse::SseUsageParser::new(proto)` / `feed(&mut self, chunk: &[u8])` / `finish(&mut self) -> UsageInfo`（增量解析，`\n\n` 事件边界，缓冲截断帧）
- `sse::parse_json_usage(proto, body: &[u8]) -> UsageInfo`（非流式响应）
- `usage::UsageRecord { ts, key, protocol, model, provider, upstream_model, status, latency_ms, ttft_ms, input_tokens, output_tokens, cache_read_tokens, cache_creation_tokens, error }`（serde，key 字段记 name 不记 key 本体）
- `usage::UsageSink::spawn_writer(path) -> io::Result<UsageSink>`（mpsc(256) + tokio task 追加写 jsonl，先建父目录）/ `record(&self, UsageRecord)`（try_send，满则 warn 丢弃）

**要点:**
- Anthropic usage 来源：`message_start` 事件的 `message.usage`（input + cache_*）与 `message_delta` 的 `usage.output_tokens`。OpenAI 双 shape 都要认：chat completions 是 `usage.{prompt_tokens, completion_tokens}`，Responses API 是 `usage.{input_tokens, output_tokens}`（按 key 存在性探测）。
- 容错铁律：`[DONE]`、未知事件、截断帧、坏 JSON 一律跳过——解析失败只丢统计，绝不影响透传字节。
- tee 实现：proxy SSE 分支 `bytes_stream().map(...)` 闭包内喂 parser 并记 TTFT（首个 chunk）；闭包捕获的 `UsageFinalizer` 结构实现 `Drop`——流结束**或客户端断开**都结算（写 record + `quota.record_tokens`），无需 pin_project。
- 非 SSE 分支：缓冲 body 后 `parse_json_usage` + 结算。上游 4xx/5xx 也记 record（status 承载错误语义，error 字段留给网关侧失败如 connect 502）。
- usage_file 父目录由 `spawn_writer` 创建；build_state 调它，失败 → Config 错误拒绝启动。

**测试：**
- sse.rs inline 约 7 例：Anthropic 完整流（input+cache+output）／Anthropic 跨 chunk 截断帧重组／OpenAI chat shape／OpenAI responses shape／`[DONE]` 与未知事件容忍／坏 JSON 容忍／parse_json_usage 双协议。
- usage.rs inline 1 例：spawn_writer 写两条 record → 文件两行合法 JSON 且字段齐全（用 tempfile）。
- proxy 集成 1 例（可并入 Task 9）：SSE 请求完成后轮询 usage.jsonl 出现一行，token 数与 fixture 一致。

**Commit:** `feat(gateway): SSE usage tee 与 jsonl 用量落盘（断流安全结算）`
