## Why

sebas 至今只能在主控所在的机器上跑 agent：core 是唯一 spawn 执行体的进程，`project_dir` 在 spawn 前于本机 `stat`，会话状态与子进程同机同命。这挡住了一整类用法——把重活、内网机器、别人的机器当作执行位，而操作面与凭据仍然集中在一处。

## What Changes

- 新增**独立二进制** `sebas-node`（执行节点）：不随主控二进制分发，节点机上不出现也不需要主控角色（core / webui / router / im）；节点出站 websocket 连接主控，主控不需要能反向访问节点。
- **权威分域**：主控持会话身份（发放会话 id）、期望态（mode / 模型）与呈现；节点持执行事实（子进程寿命、有序 turn 日志、审批悬空状态、执行结果）。
- **会话协议为粗粒度**：节点自建会话、自己组 turn，主控发 prompt、收（节流合并后的）turn 流；节点日志保持完整，主控可按 seq 回拉任意精度。
- **断连与重启**：ws 断开不杀子进程，主控重启不影响远端执行；重连与重启走同一套对账（状态=幂等快照，历史=按会话 seq 增量追加）。
- **mode 决定审批**：会话带 mode（ask / edit / allow / auto 等）；mode 是主控持有的期望态，节点回报实际生效态，执行体强制不了就如实降级。审批一律上行主控，主控不可达时无限期 park；节点永不自我放行（无本地审批出口）。
- **项目跨机**：项目注册条目成为 `(节点, 路径)` 具名引用，路径可用性判定在被 spawn 的那一侧；无项目的会话落到显式配置的默认执行节点。**BREAKING**：现有项目注册语义需要本机节点的隐式补全。
- **材料与模型**：操作者级材料（全局 skills / 跨项目 memory / subagent 定义）由节点按需拉取、落在该执行体认得的位置、会话创建时钉住版本；provider 凭据默认留在节点本地，可选让节点经主控 router 出网（节点零凭据）。
- **节点本地日志**：按节点自定保留期回收，但每次回收必须上报水位线；日志重置换 epoch，两者共同保证「缺在哪、缺多少」可回答。

## Capabilities

### New Capabilities

- `execution-node`: 节点进程人格与节点本地行为——身份与配对、出站链路、能力清单、并发与诚实拒绝、provider 归属、材料落地与版本钉住、本地日志存储与保留。
- `node-session-channel`: 主控与节点之间的会话协议与对账——粗粒度会话、turn 流粒度、状态快照 vs 有序日志增量、重连与重启对账、悬空审批同步、协议版本协商。

### Modified Capabilities

- `agent-workbench`: 项目注册带节点维度、默认执行节点、节点离线呈现、悬空审批的 inbox 落位、desired/effective mode 差异可见。
- `permission-flow`: mode 作为审批前置门、远程会话的审批上行走廊、主控不可达时无限期 park、节点无本地放行入口。
- `session-lifecycle`: 远程会话的寿命与节点绑定（节点重启即会话终止）、对账不重建会话身份。

## Impact

- 新增第二个可分发产物 `sebas-node`（节点侧进程面、链路、节点本地日志存储、材料落点管理），以及它所需的 crate 边界（节点依赖图内不得出现主控角色）。
- 主控侧：会话放置、项目注册形状、审批走廊、inbox 与工作台呈现。
- 依赖既有机制，不新造：`SessionBackend` trait 缝、`agent-driver` 的 kind 注册表与可达性上报、`permission-flow` 的 fail-closed 与陈旧点击语义、webui 既有的 debounce 合并口径。
- 部署与打包：主控新增一个监听端点（节点入站）；节点新增一种安装形态，Dockerfile / CI / release 产物 / ansible 需同时覆盖两个二进制；TLS 由部署方（反代/VPN）终止，不明文跨公网。
- 术语：`openspec/glossary.md` 的「单一二进制，子命令决定人格」不再是全局事实，需按本次偏离修订。

## Non-goals

- 不做远端自治：节点不设本地指挥面，主控不在时不接受新工作（在飞执行不受影响 ≠ 节点能自己接活）。
- 不把主控角色打进节点产物：`sebas-node` 不含 core / webui / router / im 的实现与可运行入口（不是"带过去但不运行"，而是根本不带）。
- 不把 `sebas-node` 做成 `sebas` 的子命令（那会把整个主控程序带到节点机上）。
- 不做会话跨节点迁移，不做同一项目在多节点间的等价合并。
- 不做文件同步 / 项目自动 clone：项目树须已存在于节点上。
- 一个节点同时只服务一个主控（多主控留待将来）。
- v1 不做双向 mTLS / 自建 CA；节点凭据用一次性 join token 换取的长期密钥。
- 不改 router 的 provider 语义：(C) 模式只是把节点指向主控 router，router 侧无行为变化。
