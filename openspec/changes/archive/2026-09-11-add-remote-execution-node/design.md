## Context

主控侧现状（决定本设计边界的既有约束）：

- `project` 的定义就是**主机上的一个目录路径**（`agent-workbench`），会话经 spawn 携带 `project_dir`，core 在 spawn 前 canonicalize + stat（`usable_project_dir`，`src/core_channel/server.rs`）。路径必须存在于**执行 spawn 的那台机器**。
- 执行体只有两种且都在本机进程内：ACP 桥（`sebas-acp`，spawn 外部 agent 子进程）与原生内核（`sebas-agent`）。core 是会话状态的单一权威、唯一 spawn 子进程的进程。
- 会话驱动面已经是一套完整协议（`src/core_channel/protocol.rs`：Snapshot / Spawn / Message / EnsureMessage / Cancel / Close / Turns / SetFocus / SetSessionModel / StateSnapshot / StateMutation / ApprovalAnswer，事件 Snapshot / Spawned / Ok / Turns / Rejected / Event / ApprovalRequested / StateChanged），传输是本机 Unix socket；驱动侧抽象是 `sebas-webui::SessionBackend`，已有 in-process 与 detached 两种实现。
- 审批已有完整语义：`permission-flow` 的 hook 驱动请求、三档决策（allow_once / allow_session / deny）、allowlist 命中自动放行、陈旧点击、**无 responder 时 fail-closed**（实现是「responder drop 即 deny」，代码里没有超时机制）；`acp-driver` 在权限请求 parked 时暂停挂起检测。
- 仓库既有的诚实口径：通道不可达时如实回错、不伪装受理；可达性按 kind 上报（`agent-kinds list`）；期望态 vs 观测态的对账在 `watchdog` 已有先例。
- 材料侧现状：原生内核每轮注入项目级 `AGENTS.md` + `CLAUDE.md`；skills 与 subagent 在设计文档中标注为 Phase 4/5，**尚未实现**。
- 仓库的进程形态是**单一二进制、子命令决定人格**（`core` / `webui` / `router` / `im` / `run` 都是 `sebas` 的子命令，glossary 明载）。本设计**有意偏离**这条既有约束：节点作为独立可执行文件分发（见 D0）。

未定项：远程执行。节点的物理位置与主控分离后，「谁持有什么」必须先定，否则后续每条都会含糊。本设计把权威按域切开，而不是按进程切。

## Goals / Non-Goals

**Goals:**

- 让执行体可以跑在主控以外的机器上，操作面与凭据仍然集中。
- 让节点产物自足且最小：节点机上不出现主控角色（core / webui / router / im）——不是「带过去但不运行」，而是根本不带。
- 让「网络抖动」与「主控重启」不损失在飞执行，同时不引入第二份权威。
- 让远程会话在**能力边界上诚实**：能强制的强制，不能强制的如实上报（mode、材料读取时机、可达性）。
- 复用既有机制而非新造：`SessionBackend` 缝、`agent-driver` 的 kind 注册表与可达性、`permission-flow` 的 fail-closed/陈旧点击、webui 的 debounce 合并口径、watchdog 的期望态/观测态对账词汇。

**Non-Goals（设计层边界，非 proposal 范围的重述）：**

- 不做分布式一致（无 CRDT、无多写者合并）。对账模型只有两种原语：**幂等快照**与**有序追加**。
- 不做节点侧指挥面：节点不提供本地审批、本地发起会话、本地接管的能力。
- 不做项目文件同步：节点上的项目树由运维准备，sebas 不 clone/rsync。
- 不做跨节点会话迁移。

## Decisions

### D0 节点是独立二进制，不是主控二进制的子命令

**决定**：新增独立可执行文件 `sebas-node`（新的 workspace crate + binary target）。主控二进制 `sebas` 的子命令树保持不变——因此本 change **不产生 `cli-service` 的 delta**。

**理由**：节点机常常不是操作者自己的机器（内网跳板、别人的机器、临时容器）。把主控程序带过去，即便不运行，也意味着：节点机上存在一份核心实现（更大的攻击面与审计面）、发布产物体积与依赖面无谓扩大、以及「节点上其实能起一个 core」这种本不该存在的可能性。独立二进制把「节点机上有什么」变成一个**可回答且最小**的问题。

**必须偿还的账**：

- **crate 边界要重画**：节点需要执行体侧能力（`sebas-acp` 等），但其依赖图内**不得出现主控角色**（`sebas-webui` / `sebas-feishu` / `sebas-im` / `sebas-router` / `sebas-dispatch`）。共享的协议类型需要一个两边都能依赖的小 crate，否则会退化成复制粘贴。
- **打包面翻倍**：Dockerfile / CI / release 产物 / ansible 都要覆盖第二个二进制。
- **术语要改**：`openspec/glossary.md` 的「单一二进制，子命令决定人格」需修订为「主控是单一二进制；执行节点是第二个可分发产物」。
- **运维心智**：从此要能回答「这个二进制是哪一个」。

**备选**：(a) 做成 `sebas` 的子命令——被否决，这正是本决策要避免的（节点机上出现主控程序）；(b) cargo feature 门控的单二进制（`--no-default-features` 只编节点面）——保留单一二进制哲学、共享代码最省事，但产物出自同一个 crate 图，「主控代码不在节点机上」只能靠构建纪律保证，无法用 `cargo tree` 之类机械手段审计，且与你「不要带过去（虽然没有运行）」的要求正面冲突。

### D1 权威按域切分，不按进程切分

**主控持有**：会话身份（会话 id 的发行者）、期望态（mode、模型、材料版本）、呈现（工作台/inbox）、项目注册。
**节点持有**：执行事实（子进程寿命、有序 turn 日志、审批悬空状态、执行结果、节点本地 provider 凭据）。

备选：(a) 主控全权、节点无状态——被否决，因为「主控重启不影响远端执行」要求节点持有跨主控进程的状态；(b) 节点为真源、主控只是投影——被否决，因为会话身份若由节点发行，主控的 session map 变成随时可被覆盖的缓存，会话的命名/分组/归属全部失控。

**冲突解决规则**：每个域只有一个写者。身份冲突不可能发生（id 只有一个发行者）；历史冲突不可能发生（追加日志只有一个写者）。

### D2 会话协议取粗粒度（β），不搬运内部驱动词表

协议承载：节点自建会话、主控发 prompt、节点回 turn 流与状态。不承载 `AcpCommand`/`AcpEvent` 逐条词表。

备选：(a) 把 `agent-driver` 抽象过河（ws 跑完整词表）——上层零改动，但会把内部词表冻结成 wire 协议，且逐 token 事件跨网；(b) 把 ACP 多路复用到 ws——节点侧改动最小，但原生内核路径塞不进去，且违反 `agent-driver` 明文约束「no agent-client-protocol type leaks past the driver module boundary」。

代价必须承认：β 之下「支持一切 agent 功能」不再是白拿的，每一项（审批、模型热切、取消、用量、附件、错误/退出语义、transcript 归属）都要在协议里**逐项定义**。这是本设计的**主要实现风险**，任务清单必须逐项覆盖。

### D3 三层身份：节点、项目、会话

- **节点身份（i2）**：操作者在配对时确定并持久化（如 `dev-box`），重装后用同一 id 重新配对；身份稳定，连续性由 epoch 表达（见 D5）。
- **项目身份**：`(节点, 节点本地路径)` 的具名引用。路径可用性判定（`usable_project_dir`）从主控挪到**真正 spawn 的那一侧**。同一项目登记在两个节点 = 两条互不等价的项目条目；git remote 仅作元数据（显示与将来的等价判定），v1 不据此自动 clone。
- **会话身份**：由主控发行（不可伪造的 id），节点以它为主键；重连/重启按此 id 重挂，**绝不重建**。

备选：节点自生成会话 id → 主控无法在节点丢失后保持会话命名与归属的一致。

### D4 断连与重启：子进程不随链路或主控死亡

ws 断开、主控重启均**不杀**远端子进程；主控重启后远端会话继续，重连后对账重挂。节点重启 = 该节点上会话终止（进程寿命的物理边界，不做跨进程复活）。

备选：控制面租约到期即杀子进程——被否决（这条是为「主控重启即终止」设计的，本设计不取该前提）。其复杂度（租约续期、时钟、误杀）一并删除。

### D5 对账模型只有两种原语

- **状态 = 幂等快照**：节点上报当前态，主控整体替换该会话的执行事实投影。执行事实以节点为准（last-write-wins 且写者唯一）。
- **历史 = 有序追加**：每个会话一条 `seq` 单调递增的有序日志；主控持游标增量拉取；`seq` 冲突不可能出现（单写者）。
- **epoch**：节点日志被重置/重装时递增，主控据此区分「同一段历史的继续」与「一段新历史」，不会把两条时间线接成一条。
- **重连与重启走同一段代码**：对账 = 快照 + 增量拉取 + 悬空审批重报。这是「主控重启」与「网络抖动」不需要两套逻辑的原因。

### D6 mode 是会话的期望属性，能力按执行体如实降级

`desired_mode`（主控持有）与 `effective_mode`（节点上报实际生效值）分离；mode 取值 `ask` / `edit` / `allow` / `auto` 等由主控定义，节点将其翻译为执行体各自的原生模式。

**硬约束（决定了这条必须如实降级）**：native 内核有 policy engine，sebas 自己执行工具，可以**强制** mode；通用 ACP 路径仓库里只实现了 `set_config_option{model}`，没有 session mode 通道，权限请求由 agent 主动发出——**sebas 没有拦截点**。因此 ACP 会话的 mode 是「请求 agent 遵守」，不是保证。

备选：节点本地强制（对所有执行体统一 gate）——对 ACP 子进程物理上做不到，声称支持即是撒谎。

`auto` 模式 = 把该机器完全交给 agent 自主执行。它不得是默认值，且必须有审计痕迹。

### D7 审批一律上行；节点永不自我放行

- 审批请求上行主控，由 mode 作为前置门（`auto` 之下不产生审批请求）。
- **主控不可达时无限期 park**（不是超时拒绝，也不是降级放宽）：与本地 CLI「提示框一直等你」的行为一致。
- **节点没有本地放行入口**：这是安全性质——被攻陷的节点也无法自我授予权限，放行只有一个来源。
- 既有 `fail-closed on missing responder` 语义**保留给「responder 真的不存在」**（请求未知、会话已终止、回复无法关联），不适用于「主控暂时不可达」。

**必须分开写的两件事**：节点无法自我放行 ≠ 节点不会被执行任意命令。主控的 prompt 与材料 + `auto` mode = 主控对节点有实际执行权。安全边界是 **mode**，不是审批。

代价（写进运维文档与 UI）：主控永久丢失 ⇒ 该节点上处于 ask 悬空的会话**不可恢复**，节点侧没有第二条路。

### D8 模型流量默认走节点本地凭据，可选经主控 router

默认：节点持自己的 provider 配置与凭据，主控只能从节点上报的清单里选（desired/effective 同 D6）。节点持本机凭据 ⇒ 主控缺席不影响模型调用，与 D4 一致。

可选：`upstream = control-plane-router`，节点零凭据、模型流量回主控经 router 出网。收益是密钥集中、成本集中、不可信节点上不落密钥；代价是主控成为模型流量的可用性依赖（在飞的模型请求会随主控重启断流）——所以它是**显式选项**而非默认。

备选：主控下发凭据给节点——密钥扩散，否决。

### D9 材料：项目级留原地，操作者级拉取

- **项目级材料**（`AGENTS.md` / `CLAUDE.md` / 项目内 skills / 仓库内 subagent 定义）随项目树在节点本地，不过河。
- **操作者级材料**（全局 skills、跨项目 memory、全局 subagent 定义）由节点在会话 spawn 时向主控拉取，落在**该执行体认得的位置**（Claude Code 的 `.claude/` 与 `~/.claude`、原生内核走提示词注入），并在会话创建时钉住版本号。
- 主控的变更通知只携带**版本/失效信号，不携带内容**（带内容就退化成推送）。
- 诚实边界：sebas 保证「落点上的文件是最新的」，**不保证 agent 何时读它**——读不读由 agent 自己决定。

备选：主控推送（主控需知道节点拓扑与目录布局，耦合变重）；共享挂载（主控缺席 ⇒ 材料读不到 ⇒ agent 起不来，与 D4 冲突）。

### D10 会话放置是项目的函数，不是一个调度问题

项目条目即 `(节点, 路径)`，**选项目即选节点**；无项目的会话（现状：全部飞书来源）落到显式配置的**默认执行节点**。节点离线 ⇒ 新建会话**如实失败**并附成因（哪个节点、什么原因），不排队、不伪装受理。

备选：离线排队——会让操作者以为会话已在跑；且需要回答队列位置、上限、取消等一串新问题。

### D11 turn 流取节流合并粒度

默认按时间窗合并上行（100–250ms 量级，与 webui 既有 debounce 口径一致），节点侧缓冲有上限；**节点的原始日志始终完整**，主控想看清任意一步可按 seq 回拉——因此合并只是传输层行为，不损失保真度。缓冲超限时如实上报「此段已合并/可回拉」，绝不静默丢。

备选：逐 token（跨网最贵，且断连期需缓存最细粒度）；仅 turn 级结果（主控看不到进度，远程执行变黑盒——恰恰是远程最需要可见性的地方）。

### D12 节点本地日志按节点自定保留期回收，但回收必须留下痕迹

节点可自定保留期（时间/大小），过期回收；**每次回收必须上报「已回收至 seq N」的水位线**，主控据此在自己的历史里标记「此段已不可得（节点已回收）」，而不是留一个永远填不上的洞。日志重置/重装递增 epoch。

磁盘触顶时节点**如实拒绝新会话**，而不是悄悄丢历史。

**准确性承诺（写进 spec）**：主控侧历史完整性上界 = 节点保留期 ∪ 已同步部分；超出即永久缺段，但**缺在哪、缺多少是可回答的**。

备选：仅回收主控已确认的段（完整性最强，但把保留期决策权交给了主控，与「节点自定保留期」相悖）。

### D13 链路与认证

节点**出站拨号**（NAT/内网友好，主控只暴露一个端点）；一次性 join token（带过期、一次性）换取长期节点凭据，可吊销；握手携带**协议版本 + 能力清单**（agent kinds 与各自可达性、provider 清单、每种执行体能否强制 mode）；版本不兼容时**如实拒绝接入**，不半工作。TLS 由部署方终止（反代/VPN），sebas 不承诺自带 TLS，**不明文跨公网**。

一个节点同时只服务一个主控（多主控为 Non-goal）。

**入站端点由 core 托管**（不在 webui）：节点链路上跑的是会话级操作，而 core 是会话状态的单一权威、也是唯一 spawn 执行体的进程——远端节点本质上是「远程执行体宿主」，天然该与 core 对话。若改由 webui 托管，webui 会从「观察/驱动客户端」变成「中继」，且远程执行会额外依赖 webui 在线。代价是 core 首次获得一个 HTTP/WS 入站面（此前只有 Unix socket），因此它必须沿用仓库既有的鉴权口径（一次性 token 换长期凭据）而不是裸信任网络位置。

**默认关、默认仅回环、坏地址在解析期就被拒**：这是一个新的网络入站面，打开必须是显式动作；`listen` 解析失败在启动前报错，不让它拖到 ready 之后。**第一台节点靠 bootstrap token 接入**：注册表既无节点也无待用 token 时签发一次并记进日志（沿用 webui 首启凭据「只显示一次」的既有形态，带 TTL），之后不再重复吐凭据——否则每次重启都会在日志里留下一个可用的配对凭据。完整的签发/吊销管理入口（通道 RPC + 服务页）是 2.7。

### D14 节点侧资源边界：并发上限 + 诚实拒绝

节点配置最大并发会话数；超限返回 typed rejection 并指名成因，不排队、不挤占既有会话。

## Risks / Trade-offs

- [主控成为非 auto 会话的可用性依赖] → 明示于 UI 与运维文档；`auto` 模式是正当出口；主控缺席期间在飞执行不受影响（只有决策受影响）。
- [主控永久丢失 ⇒ ask 悬空会话不可恢复] → 写进运维文档与 UI 提示，不让机主自己发现。
- [r2 保留期 ⇒ 主控可能永久缺段] → 回收水位线上报 + epoch，使缺口可回答；不做静默丢失。
- [「节点执行任意命令」的实际权力归主控（prompt + 材料 + auto）] → 在 spec 中与「节点无法自我放行」分开陈述，避免用安全性质掩盖真实权力面。
- [β 之下「一切 agent 功能」需逐项定义，漏一项就是功能缺口] → 任务清单逐项覆盖（审批/模型/取消/用量/附件/错误语义/transcript 归属），并以协议版本协商兜住演进。
- [材料落点依赖各执行体的目录约定] → 为每种执行体维护落点表；执行体不支持材料落点时如实拒绝而不是静默忽略。
- [节点上项目树须由运维准备] → 项目注册在做路径判定时即如实报错；不实现 clone/同步。
- [协议是新的、无现成词表] → 版本协商 + 不兼容如实拒绝；v1 只承诺接入同版本节点。

## Migration Plan

1. **本机路径兼容**：既有项目注册项（只有路径、没有节点维度）迁移时补一个**本机节点**的隐式条目（`local`），旧行为不变；本机执行继续走进程内路径，不经过 ws。
2. **渐进引入**：`sebas-node` 与 `node-session-channel` 可独立部署；主控在没有任何节点注册时行为与今天完全一致（无节点 = 无远程面）。
3. **回滚**：移除节点注册即可让远程会话面消失；远程会话的历史副本留在主控，节点侧日志按保留期自然回收。已存在的远程会话在回滚后表现为不可达（节点离线语义），不做特殊处理。
4. **文档**：运维需知的三条——如何配对节点、TLS/网络要求、主控丢失的后果。
