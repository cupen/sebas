## Context

动机见 `proposal.md` — Why。设计相关的事实：

1. **今天的重置是不可逆的**：`migration.rs:89-101` 在 `SyncFail::Incompatible` 时调用 `reset_and_rebuild`（`:208-222`），删除 `""` / `"-wal"` / `"-shm"` 三个文件后重建空 schema；既有测试 `extra_column_resets_database`（`:481-511`）断言原有行**不存活**。
2. **隔离手法已有先例**：`src/session_boot.rs:315-323` 把损坏的 state JSON 改名为 `<path>.corrupt-<unix>` 而不是删除。同一思路可直接用于库文件。
3. **迁移词表现状**：只有 `add_column_sql`（`:263-276`）。改名列、删列、类型变更都会落入「缺列/多余列/类型不符」→ 重置。
4. **`auth.db` 完全不在迁移机制内**：`CREATE TABLE IF NOT EXISTS` + `PRAGMA user_version`，无 diff、无重置路径。
5. **产品状态：尚未发布正式版**——这是本 change 把其它加固全部推迟的唯一理由。

## Goals / Non-Goals

**Goals:**

- 把「重置」从不可逆变成可逆，代价最小。
- 让日志如实说明发生了什么、旧数据在哪。

**Non-Goals:**

- 不扩迁移词表；不做 fail-closed；不做重置策略；不统一版本语义；不动 `auth.db` 机制；不做数据导入。

## Decisions

### D1 只做隔离，不做词表扩张——理由是「没有需要保护的对象」

原设计（改名列 / 删列 / 类型变更词表、未声明多余列的 fail-closed、每库重置策略、`auth.db` never-delete、版本语义统一）的**唯一价值是保护既有安装的数据**。产品尚未发布，因此不存在既有安装：改列类型或改名时直接重置正是开发期的正常节奏，词表带来的复杂度换不到任何东西。**推迟全部**，触发条件见 D3。

### D2 隔离而非删除：便宜、可逆、且与既有先例一致

`reset_and_rebuild` 改为先改名（库文件与 `-wal` / `-shm` 一并，用同一时间戳），再重建。**理由**：成本约三行，但把「开发期一次 schema 演进清掉本地项目/provider/会话映射」变成「可手工恢复」；且与 `session_boot.rs` 的既有隔离手法一致（见 Context 2）。**被否备选**：备份到独立目录（引入目录与保留期管理，超出本 change）；保持删除（不可逆，且收益为零）。

### D3 明确记录被推迟的能力与触发条件

写进 proposal 的 Non-goals，触发条件统一为：**出现需要保留数据的外部安装，或准备首个正式发布**。届时应重新评估：迁移词表（改名/删列/类型变更）、fail-closed 策略、`auth.db` 的 never-delete、版本语义统一、以及数据导入路径。这保证推迟是「记录在案的决定」而非遗忘。

### D4 既有契约逐字保留

版本值本身从不触发重置、结构比较是唯一触发点、不可打开的库拒绝启动且绝不重置、加列原位执行——四条全部不动。本 change 只改**重置动作本身**（删除 → 隔离）与日志措辞。

### D5 hive-minded 的措辞要求：日志必须说明「数据没有迁入新库」

重置后旧值**不在**新库里，只有隔离文件里有。日志与文档必须明说这点，避免「重置完以为数据还在」的误解。这是本 change 唯一容易被做错的细节。

## Risks / Trade-offs

- **[隔离文件堆积]** → 开发期可接受；日志给出路径；不引入清理策略（proposal Non-goals）。
- **[误以为重置不丢数据]** → D5 的措辞要求 + 场景「A quarantined database is recoverable」明确「需手工恢复」。
- **[既有测试断言旧行为]** → `extra_column_resets_database` 必须改写为断言「隔离文件存在且内容为重置前的库」，**不得只删断言**。
- **[`-wal` 未一并隔离导致隔离文件不含最新提交]** → 三个文件用同一时间戳一并改名；单测覆盖「重置前最近一次提交在隔离文件中可见」。

## Migration Plan

单步改动：改 `reset_and_rebuild` + 日志 + 改写一条测试。无 schema 变更、无数据搬迁。

**回滚**：revert 该提交即可。若因隔离导致磁盘告警（不会），可退回删除语义。
